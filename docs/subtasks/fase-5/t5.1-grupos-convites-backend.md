# T5.1 — Backend: Grupos Familiares e Convites
> Fase 5 | Pré-req: T4.4 | Próximo: T5.2

Cria a estrutura de grupos, sistema de convites por email (com token UUID) e aceite de convite com validação de expiração.

---

## Prompt

```
No BolsoFirme (Node.js + Express + TypeScript + Prisma + Zod + Nodemailer), arquitetura DDD, implemente grupos familiares.

Novos modelos Prisma:
- Group: id (uuid), name, createdBy (FK User), createdAt
- GroupMember: id, groupId (FK Group), userId (FK User), role ("ADMIN"|"MEMBER"), joinedAt (único: groupId+userId)
- GroupInvite: id, groupId (FK Group), email, token (uuid único), status ("PENDING"|"ACCEPTED"|"EXPIRED"), expiresAt (now+7dias), createdAt

Endpoints (todos autenticados exceto GET /invites/:token):
- POST /groups                      → criar grupo (auto-cria GroupMember ADMIN para o criador)
- GET  /groups                      → listar grupos do usuário logado
- GET  /groups/:id                  → detalhes + membros
- POST /groups/:id/invites          → convidar por email (gerar token UUID, enviar email, expirar em 7 dias)
- GET  /invites/:token              → verificar convite (público) — retornar groupName, inviterName ou 404/410
- POST /invites/:token/accept       → aceitar convite (autenticado) — criar GroupMember + marcar ACCEPTED
- DELETE /groups/:id/members/:userId → remover membro (apenas ADMIN do grupo)

Regras de negócio:
- Usuário só pode estar em 1 grupo por vez (verificar antes de aceitar convite)
- Convite expirado → status 410 Gone
- Não pode convidar email de quem já está em um grupo

Email via Nodemailer (configurar .env: SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASS):
Template simples com link: [APP_URL]/invites/[token]

Schemas Zod em packages/shared/src/schemas/group.ts.
```
